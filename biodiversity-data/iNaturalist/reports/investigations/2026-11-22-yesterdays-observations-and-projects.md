# Investigation: yesterday's observations, rarity and projects to join

Written by hand from one-off API queries on 22-23 Nov 2026. Nothing here is regenerated by the pipeline in [`../../scripts/`](../../scripts/README.md), and the numbers are a snapshot of live iNaturalist data for [`andreiastra`](https://www.inaturalist.org/people/andreiastra) at that time.

The questions, in order:

1. How many new species did I see yesterday (21 Nov 2026)?
2. Do yesterday's observations have all the recommended fields?
3. Which of them are the rarest?
4. Which iNaturalist projects should I join?

All 23 observations from 21 Nov were made at Lough Hyne, Co. Cork. Nothing was written to iNaturalist or to this repo while investigating. The throwaway scripts lived in `/tmp` and are described under [Method](#method).

---

- The searches found no Seasearch or Explore Your Shore project on iNaturalist, so neither is on the list. Your notes call both complementary schemes, and they may run outside iNaturalist.

## Method

All data came from the public iNaturalist API (`https://api.inaturalist.org/v1`), with no authentication and about one request a second. The scripts were throwaway files in `/tmp`, not part of the repo.

| Step | Endpoints | Notes |
|---|---|---|
| New species | `observations/species_counts` with `d1=d2=2026-11-21`, then the same with `d2=2026-11-20` | A taxon is new if it has no earlier record |
| Fields | `observations` for the day, reading `ofvs`, `annotations`, `description` and `place_guess` | Run twice, before and after your edits |
| Rarity | `observations/observers` and `observations` with `taxon_id`, `place_id=6718`, `verifiable=true`, plus a world count | The same counts as [`rarity_underwater_ireland.py`](../../scripts/rarity_underwater_ireland.py) |
| Projects | `projects?q=<keyword>`, then `observations?project_id=<id>&user_id=andreiastra&per_page=0` | Counts saved to a JSON file so a stopped run can resume |

**Problems along the way**
- The first project check timed out on one call and printed nothing. It was rerun with retries and visible errors.
- A size filter used a field the projects API does not return (`observations_count`), so it kept nothing. I replaced it with a filter on project type.
- One background run was cancelled partway. Saving per-project counts to a file let the final run resume.

**Not done**
- The recommended fields were not added to any observation.
- No project was joined.
- The scripts were not added to `scripts/`. If this check should be repeatable, the field check and the project-overlap count are the two worth turning into scripts.
