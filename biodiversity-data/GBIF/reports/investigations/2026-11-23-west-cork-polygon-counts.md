# Investigation: underwater species in the West Cork polygon, from counts

Written by hand from one-off API queries on 23 Nov 2026. Nothing here is regenerated by the pipeline in [`../../scripts/`](../../scripts/README.md), and the numbers are a snapshot of live GBIF data at that time.

The questions:

1. Which underwater (marine) species are in the West Cork polygon, and which are the most photographed?
2. Can this be answered with counts instead of downloading every record?

The area is `WEST_CORK_POLYGON` in [`config.py`](../../scripts/config.py): a polygon drawn in the GBIF occurrence search around West Cork and its coastal waters. It replaced the GADM boundary `IRL.4.9_1`, which covers land only and so missed the sea.

```
POLYGON((-9.51086 51.84839,-10.38407 51.57121,-9.66406 51.32488,-8.37264 51.58549,-8.53962 51.86447,-9.51086 51.84839))
```

Filters on every query: `occurrenceStatus=PRESENT` and `mediaType=StillImage`, from every recorder and dataset.

---

## 2. Counts instead of records

Yes. The `facet` parameter returns counts per species without downloading any records:

```bash
G='POLYGON((-9.51086 51.84839,-10.38407 51.57121,-9.66406 51.32488,-8.37264 51.58549,-8.53962 51.86447,-9.51086 51.84839))'
curl -s -G https://api.gbif.org/v1/occurrence/search \
  --data-urlencode "geometry=$G" \
  -d occurrenceStatus=PRESENT -d mediaType=StillImage \
  -d limit=0 -d facet=speciesKey -d facetLimit=100000 -d facetMincount=1
```

| Approach | Requests | Time |
|---|---|---|
| Download every record ([`cork_underwater.py`](../../scripts/cork_underwater.py)) | about 81 pages of 300 records, about 1.9 MB each, then 3 lookups per species | stopped by hand after about 40 minutes with no report |
| One `facet=speciesKey` call | 1 (about 65 KB) | under 1 second |

After the facet call, the only slow part is the marine check: one `speciesProfiles` request per species in the polygon, which took a few minutes at 8 requests in parallel. Common names and classes were then fetched for the marine species only.

**What counts cannot do.** There is no copy removal (it needs recorder and date per record), and no thumbnails or per-photo links. Photos by year and by dataset need `facet=year` and `facet=datasetKey` calls, which are also cheap.

## Caveats

- **Marine flag.** A species with no marine value in its GBIF profile (some seaweeds) is left out, and a marine species photographed from the shore is included.
- **Coordinate uncertainty.** Records near the polygon edge may come from land or sea just outside it.
- **Counts are live.** GBIF re-reads iNaturalist periodically, so the figures change.

## Method

Nothing was written to GBIF or to this repo while investigating. The scripts read the git-ignored `scripts/.cache/species_profiles.json` for species already checked, but did not write to it. The throwaway scripts lived in `/tmp`:

- `facet.json`: the `facet=speciesKey` response above.
- `cork_counts.py`: checks `speciesProfiles` for each species key, then fetches the name, class and English common name for the marine ones, and prints the totals. The first run stopped after 1,000 profiles because its shell session ended; a second run in a background process finished.
- `n.json`: the same facet call with `taxonKey=980` for the nudibranchs.

[`cork_underwater.py`](../../scripts/cork_underwater.py) was **not** run to completion in its original form. It downloaded every record, so it was too slow for this polygon. It has since been rewritten to use the facet counts, and it now writes [`../cork_underwater.md`](../cork_underwater.md) in about 3 minutes. The report matches this note: 446 species and 5,080 photos.
